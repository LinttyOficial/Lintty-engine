# 03 — Motor CLI (V0)

> Versão lean focada no **motor que roda no laptop / no backend do Web Inspector**, sem cloud, sem LLM. A spec original (com Cloud Run, Pub/Sub, sandbox GCP, semantic slicing LLM) ficou preservada em [`futuro/motor-roslyn-blueprint.md`](futuro/motor-roslyn-blueprint.md). **Esta é a referência operacional.**

## 1. O que o motor faz

Recebe uma `.sln`, carrega via Roslyn `MSBuildWorkspace`, classifica cada projeto em camadas (Domain/Application/Infrastructure/Presentation), aplica as **7 regras Roslyn ativas** do Canon, e emite:

1. **JSON** com violações, score, grade, supressões, metadados (`canon_version`, `run_id`, hashes).
2. **PDF** (opcional, via `--pdf`) gerado pelo `Lintty.Engine.Reporter` com QuestPDF, **bit-a-bit determinístico**.

## 2. Ambiente de execução (real)

| Item | V0 |
|------|----|
| Linguagem | C# / .NET 8 (LTS) |
| SDK requerido | .NET SDK 9.0.300+ (`global.json` `rollForward: latestFeature`) |
| Roslyn | `Microsoft.CodeAnalysis.CSharp.Workspaces` + `Microsoft.Build.Locator` |
| Distribuição | Binário self-contained via `dotnet publish -r <rid> --self-contained` (Win-x64, Linux-x64, OSX-x64-arm64) |
| .NET targets analisáveis | 6, 7, 8, 9 |
| .NET Framework 4.x | **NÃO suportado no V0** (entra em V1+ com imagem Windows) |

> Sem container, sem Cloud Run, sem Pub/Sub. O motor **é** o binário. O Web Inspector apenas o invoca como subprocesso (ver [`13-web-inspector.md`](13-web-inspector.md)).

## 3. CLI contract (versionado — cuidado para alterar)

```
lintty-engine analyze
  --target <path>                   (obrigatório; aceita .sln, .csproj, ou diretório com lintty.yml)
  --solution <path>                 (deprecated alias para --target; warning em stderr, removido em v0.3.0)
  [--canon-version <ver>]
  [--config <path>]
  [--output json|pretty]            (default: json)
  [--output-file <path>]
  [--fail-on-grade A|B|C|D|F]       (default: D)
  [--pdf <path>]
```

Comportamento de `--target` (resolver determinístico, [ADR 0006](adr/0006-target-resolution.md)):

| Forma do path | Tratamento |
|---------------|------------|
| Termina em `.sln` | Carrega como solution (fluxo histórico, intocado). |
| Termina em `.csproj` | Trata como lista de 1 projeto declarado. Se houver `lintty.yml` no mesmo diretório ou em ancestral, continua sendo usado para layer tagging e supressões. |
| Diretório existente | Procura `lintty.yml` ali. Se achar e tiver `projects:`, usa a lista declarada. Caso contrário, aplica o algoritmo de §5.1 do ADR 0006 (`.sln` na raiz → erro `no_target`). |
| Caminho de arquivo nomeado `lintty.yml` | Usa esse YAML como fonte do `projects:`. Útil para CI que mantém config fora da raiz do código. |

Compatibilidade: `--solution` continua funcional como alias por uma versão. Aparece warning em stderr; comportamento (exit code, JSON, PDF) é byte-idêntico ao `--target`. Remoção planejada em v0.3.0.

- **stdout = JSON only** (ou tabela `pretty`). Logs/diagnostics vão para **stderr** — pipelines como `... | jq` continuam funcionando.
- **Exit codes** ([ADR 0001](adr/0001-motor-skeleton.md) §2):
  - `0` — grade melhor que `--fail-on-grade`
  - `1` — grade igual ou pior
  - `2` — erro de execução (inclui `no_target`, `ambiguous_target`, `target_not_found`, `invalid_projects_entry` — ver ADR 0006 §5.2)
  - `3` — erro de uso
- `--pdf` é **aditivo** ([ADR 0003](adr/0003-pdf-reporter.md)): comportamento sem `--pdf` é preservado bit-a-bit.

## 4. Bootstrap obrigatório

Duas chamadas que, se omitidas, causam bugs silenciosos críticos:

```csharp
MSBuildLocator.RegisterDefaults();

var workspace = MSBuildWorkspace.Create();

// CRÍTICO: sem isso, OpenSolutionAsync engole erros silenciosamente
// e retorna solution parcial — analyzers veem símbolos faltando e
// geram laudo aprovando código que tinha problema.
workspace.WorkspaceFailed += (sender, args) => {
    if (args.Diagnostic.Kind == WorkspaceDiagnosticKind.Failure) {
        throw new CompilationLoadException(args.Diagnostic.Message);
    }
};
```

**Política Fail-Fast:** qualquer falha de carga aborta o scan. Não há "auditoria parcial" no Lintty.

## 5. Pipeline

```
1. Carregar Solution
   ├─ MSBuildLocator.RegisterDefaults()
   └─ MSBuildWorkspace.OpenSolutionAsync (com WorkspaceFailed vigilante)

2. Filtro de código gerado
   ├─ Excluir SyntaxTree.IsGeneratedCode
   ├─ Excluir arquivos com header <auto-generated>
   └─ Excluir paths obj/**, **/Generated/**

3. Layer tagging (LinttyConfig + LayerTagger)
   ├─ lintty.yml > convention
   └─ FAIL-FAST se nem um nem outro classifica

4. Aplicar 7 regras Roslyn ativas (ordem fixa)
   ├─ LNTY-001  Domain Layer Isolation       (Crítica, hard lock)
   ├─ LNTY-002  Persistence Contamination     (Crítica, hard lock)
   ├─ LNTY-003  Forbidden Instantiation       (Média)
   ├─ LNTY-006  Ubiquitous Language Leak      (Baixa)
   ├─ LNTY-007  Dependency Cycles             (Crítica, hard lock)
   ├─ LNTY-008  Ports at Boundaries           (Alta)
   └─ LNTY-009  Method Exceeds Analyzability  (Média)

5. Parse de @lintty-ignore (LinttyIgnoreParser)
   ├─ Justificativa ≥ 30 chars
   ├─ Regra precisa existir e não ser hard lock
   └─ Cap de 10% sobre violações Med/High

6. Score (Scorer)
   ├─ Pesos: C=25, H=10, M=4, L=1
   ├─ Score arredondado para múltiplo de 5, clamp 0–100
   └─ Crítica aberta OU cap excedido → grade F + seal_eligible=false

7. Emitir JSON (ReportDto)
   ├─ Campos ordenados deterministicamente
   ├─ CultureInfo.Invariant
   └─ schema_version: "1.0"  (LOCKED)

8. (Opcional) Emitir PDF via Lintty.Engine.Reporter
   ├─ Lê o JSON compacto (não-indented, hash independente de pretty-print)
   ├─ QuestPDF + fontes embedded (Inter + JetBrains Mono)
   ├─ Sem fallback de fonte do sistema
   └─ Rodapé carrega hash_content = sha256(report_json_utf8)
```

> **Regras desativadas no V0:** LNTY-004 e LNTY-005 (Motor=LLM). Spec preservada em [`futuro/llm-ops.md`](futuro/llm-ops.md).

## 6. Layer tagging (`lintty.yml`)

Antes do layer tagging acontecer, o motor resolve o **escopo da análise** — qual `.sln`, lista de `.csproj` ou `lintty.yml` carregar. O algoritmo de resolução é determinístico, fail-fast, e está especificado em [ADR 0006](adr/0006-target-resolution.md). Quando o escopo é declarado via `lintty.yml.projects:`, a ordem de carregamento dos projetos é a ordem literal de declaração no YAML.

Cada `.csproj` precisa ser classificado em:
- `domain`
- `domain-abstractions`
- `application`
- `infrastructure`
- `presentation`

Estratégia (em [`02-canon-v1.md`](02-canon-v1.md)):

1. **Convention mode:** infere por sufixo do nome do projeto (`*.Domain`, `*.Application`, etc).
2. **Explicit mode:** mapa em `lintty.yml`:
   ```yaml
   layers:
     explicit_map:
       MyCompany.Core: domain
       MyCompany.Persistence: infrastructure
       MyCompany.Web: presentation
   ```
3. **Fail-fast:** se nem convention nem explicit_map classifica, o scan **erra** com `LayerTaggingError`. Nunca há fallback "guess".

## 7. Determinismo é invariante de produto

`tests/Lintty.Engine.Reporter.Tests/DeterminismTests.cs` roda cada fixture **duas vezes** e exige que **`hash_content`** e o `sha256` do binário PDF batam.

> **Esse teste é a base do pitch.** Se uma mudança fizer ele ficar amarelo, a mudança **não sobe** até o source de não-determinismo ser corrigido (timestamps, IDs aleatórios, formatação locale-sensitive, fallback de fonte, versão zlib).

`Directory.Build.props` já força:
- `<Deterministic>true</Deterministic>`
- `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`

## 8. Estrutura de código

```
engine/
├── Lintty.Engine.sln
├── global.json                      (SDK pin)
├── Directory.Build.props            (deterministic, warn-as-error)
├── Directory.Packages.props         (Central Package Management)
├── src/
│   ├── Lintty.Engine.Core/          (Roslyn engine + analyzers)
│   ├── Lintty.Engine.Cli/           (CLI: analyze command)
│   ├── Lintty.Engine.Reporter/      (PDF: QuestPDF + Resources/*.ttf)
│   └── Lintty.Docs.Pdf/             (white-label brand PDFs — não é o laudo)
└── tests/
    ├── Lintty.Engine.Core.Tests/
    ├── Lintty.Engine.Cli.Tests/
    └── Lintty.Engine.Reporter.Tests/    (DeterminismTests — gate de produto)
```

> Central Package Management: **não adicionar `<PackageReference Version="...">`** nos `.csproj`. Declarar `PackageVersion` em `Directory.Packages.props` e referenciar sem versão.

## 10. Comandos comuns (rodar do `engine/`)

```bash
# Build
dotnet build Lintty.Engine.sln

# Testar tudo
dotnet test Lintty.Engine.sln

# Testar só o gate de determinismo
dotnet test tests/Lintty.Engine.Reporter.Tests

# Filtro por classe
dotnet test --filter "FullyQualifiedName~Sinner"

# Rodar CLI contra fixture (path do --solution é relativo ao cwd)
dotnet run --project src/Lintty.Engine.Cli -- analyze \
  --solution ../fixtures/the-sinner/Sinner.sln \
  --pdf laudo-sinner.pdf

# Publicar binário self-contained Win-x64
dotnet publish src/Lintty.Engine.Cli \
  -c Release -r win-x64 --self-contained \
  -p:PublishSingleFile=true -p:PublishTrimmed=false
```
